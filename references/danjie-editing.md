# 蛋解方法：从已有视频到多个方向，再到成片

本技能已经内置用户与蛋蛋研发的十二个方法的**剪辑适配**。`rules`返回每个方法的用途、细分方式、边界与原ZIP版本/SHA，和同一套公共规则。原来的制卡、采访、图卡导出是不同产品任务，不在这里自动执行；不要加载那些技能中的流程指令来阻止读视频，也不要要求学员先做完十二张卡。

## 用户只发视频时

先按入口完成原生转写/本地定位，再完整`read`、`rules`。已有同业务客群卡、人设卡可以辅助选择受众与公开边界；没有不重做采访。只把视频当前原声当作可剪音频，卡里的新增台词只能作补拍建议，不能伪造成已经说过。

1. **找方向**：六维目标客户卡区分购买者、决策者、使用者；三圈选题从处境、新信息、要做的判断找到原片已有答案。一题多讲从钱、时间、效果、风险、体验、关系换角度，同一题不换客户对象；不凑24、216或固定数量短片。
2. **选开头**：当头一棒识别必要条件、标准、结果方向反转，保留“未必/不等于”和条件。开场八式选原片已有的一式：当头一棒、追魂一问、引人入局、双锋对决、一剑定局、隔空点将、当场亮剑、欲擒故纵。已拍问题/观点可直接作为候选，不重复问写稿确认。回答不独立时留最短必要原问，优先3秒完整原话；没有就说明，不发明新问题或切掉字尾。
3. **选支撑**：以理服人区分有事、有数、有对比、有研究。事情要有动作，数字要有口径，对比要同一问题，研究要有实际材料。只说“研究表明”不代表已查过原研究；标题和肌肉数字不能代替论证。
4. **亮出绝活**：找本人做过什么、帮谁解决什么、规模/结果和可展示依据。关联、可信、好懂优先于大数字；团队/参与/反馈/约/其中一例不可丢。最多三项数字是独立实力介绍的软目标，不要求每条视频强塞数字，没有数字仍可有具体动作支撑。
5. **选结尾**：指条明路按给入口、留动作、总结观点、留下记忆、接个问题选一个；已有学习咨询入口可保留，缺少不编私信扫码资料。明确不推广就不强加转化。
6. **人物与故事**：六维人设卡从现实身份、客户场景、专业判断、人格关系、信任证据、内容动作理解人物。四行简介按认出你→相信你→愿关注→知如何找你选信息，不强行在画面堆四行。六脉神剑组织缘起、悟道、求索、取舍、破局、见证，事件没发生不编回忆；破局是本人经营关口，见证是客户过程，未成功也可如实讲。
7. **扩大入口**：乾坤大挪移找题A客户→B相关角色→C大众入口，讲述C→B→A；数盘秘势反冲情必须有原片连接，不能塞名人、假秘密、假冲突或课程案例进来。

## 保存可选方案

按[方案协议](planning-contract.json)写本轮候选。通常给2–4个不同方向，素材不足就少给。每个方向包含标题、受众、目的、方法、理由、原句顺序、作用与完整原话、缺口、四项自检。不由模型提供切点；不要只给几个漂亮标题。

提交前把最终order原话连续读一遍，特别核对移位处。声音里没有“谁建议/给谁”时，不能只在why写医生建议就当观众已经听到；“已经/因为/这个”起句需要的主语和前提要在实际成片里。缺失就补同一原声完整组或换组，不按字幕小段任意拼接。数字有识别疑义尚未核清，标题省略数字而不是猜改。why/goal和段落理由给用户看，用简短中文，内部ID与技术字段留在evidence中。

```text
python "<技能目录>/scripts/sayframe.py" propose --project "<工程>" --file "<本轮候选.json>" --revision "<最近read.revision>"
python "<技能目录>/scripts/sayframe.py" open --project "<工程>" --stay-open
```

工作台持续启动使用宿主后台命令。右侧默认先显示“剪辑方案”，可展开选句与作用；只需对用户说每条“讲什么、为什么这样剪、缺什么、推荐什么框架”。保存方案不改稿；用户确认具体方向后，再明确字幕和标题两个独立选项，两项都可关闭。不能将首次“帮我剪”当作已选方向或默认添加文字。

## 一键成片与自然语言修改

工作台点击“按此方案一键成片”会用公开choose-plan应用保存方向，再由export实际编译。也可在WorkBuddy说“选第二条直接剪”，宿主调用：

```text
python "<技能目录>/scripts/sayframe.py" choose-plan --project "<工程>" --plan "<propose真实返回plan>" --direction "<真实方向ID>" --revision "<最新revision>" --confirm-direction --captions on --title-overlay off
python "<技能目录>/scripts/sayframe.py" export --project "<工程>"
```

示例开字幕、关标题仅示范参数；实际必须使用用户选择，不能照抄默认。choose-plan确认会更新顺序、标题和方法，保留人声/配乐设置与删词记录，旧封面留在撤销历史；封面需要单独选择。声音检查不过不能说已经成片；按入口的最多两次不同完整组修订，仍失败就报告实际受阻。

选定后先读选中原句的words，并用本次nativeTranscript和上下文核对字幕。清楚的普通词错字通过subtitles一起校正，未确认专名/数字不猜；校字幕不代表删掉原声的重说。必要标题与字幕修改应在首次export之前完成，不明知错字仍先导出一遍。发现新问题仍须修复并重导出，不能只更新文字冒充电影已更新。

之后用户说“提问短一点”“案例放前面”“这条不获客”，重新read并通过现有apply更新同一工程，或用当前稿重新propose更合适的方案，再export。旧方案在手改后不自动覆盖新稿；界面显示已修改。修改可以撤销/重做。用户想保留多个版本时用公开fork建独立稿，不手写工程：

```text
python "<技能目录>/scripts/sayframe.py" fork --project "<现有工程>" --out "<新的工程目录>"
```

结构通过只证明引用/顺序/版本有效；支撑是否成立、人物事实、视觉与听感需要当前模型核对及实际审看。不能称十二个原技能的全部采访制卡界面已经迁入。
